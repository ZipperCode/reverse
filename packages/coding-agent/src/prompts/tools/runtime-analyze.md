Cross-runtime deep inspection and analysis for Flutter (AOT), React Native / Hermes, and Unity IL2CPP applications. Composes established upstream reverse engineering engines (`hbctool`, `hermes-dec`, `Il2CppDumper`, `Blutter`) with offline format validation, version detection, and structured artifact generation.

Actions:
- `inventory`: Offline inspection of mobile packages (APK, AAB, IPA), directories, or standalone binary artifacts to detect cross-platform runtimes and versions. Distinguishes plain React Native JavaScript bundles vs binary Hermes Bytecode (HBC), Flutter Dart AOT snapshots vs generic native `.so` libraries, and Unity IL2CPP binary + metadata pairs.
- `hermes`: Inspects and disassembles React Native Hermes bytecode (`.hbc` or `index.android.bundle`). Reads the HBC magic (`0x1F1903C103BC1FC6`), extracts bytecode version and source SHA-1 hash, checks version compatibility against `hbctool` (HBC 59, 62, 74, 76) and `hermes-dec` (HBC 61–96), and generates bounded disassembly artifacts. Distinguishes plain JS text from binary HBC without misrouting.
- `il2cpp`: Analyzes Unity IL2CPP binaries (`libil2cpp.so` or `GameAssembly.dll`) paired with `global-metadata.dat`. Verifies metadata sanity magic (`0xFAB11BAF`) and version, executes `Il2CppDumper` to extract C# type definitions (`dump.cs`), C++ headers (`il2cpp.h`), and symbol mapping (`script.json`), and provides direct script handoff (`ghidra.py`, `ida_with_struct.py`) to `ghidra_inspect` or IDA.
- `flutter`: Disassembles and recovers symbols from Flutter Android AOT compiled snapshots (`libapp.so` + `libflutter.so`) using `Blutter`. Validates target architecture (Android arm64-v8a only), extracts Dart VM snapshot hashes, and generates assembly listings (`asm/`), object pools (`objs.txt`, `pp.txt`), and Frida hook templates (`blutter_frida.js`). Reports structured compatibility diagnostics and manual prerequisite setup if backend or matching Dart VM is absent.

Selection and parameters:
- `path`: Target file or directory (APK, bundle, ELF, or folder).
- `metadata_path`: Optional path to Unity `global-metadata.dat` (for `il2cpp` if not adjacent to binary).
- `engine_path`: Optional path to Flutter `libflutter.so` (for `flutter` if not adjacent to `libapp.so`).
- `output_dir`: Custom destination directory for analysis artifacts (defaults to `./artifacts/runtime_analyze/<runtime>/<target>/`).
- `format`: Output format, `markdown` (default) or `json`.
- `limit` / `offset`: Pagination for listed types, symbols, or files.
- `timeout`: Subprocess timeout in seconds (default 60, max 300).
- `max_bytes`: Maximum captured output bytes (default 262144, max 4194304).

Safety & boundaries:
- Offline and bounded: Targets and sample binaries are immutable. Disassembly artifacts are written to dedicated artifact folders rather than dumped into the conversation context.
- Genuine execution: Invokes detected local binaries without silent auto-cloning or unapproved background network compilation. Reports structured missing dependencies with trusted install commands.
- Engine handoff: Script assets generated by IL2CPP dumping (`ghidra.py`) are handed to persistent static engines (`ghidra_inspect`) for deeper disassembly.

Upstream references:
- hbctool: https://github.com/bongtrop/hbctool
- hermes-dec: https://github.com/P1sec/hermes-dec
- Il2CppDumper: https://github.com/Perfare/Il2CppDumper
- Blutter: https://github.com/worawit/blutter
